# The OpenHealth dashboard — running it as an app (no manual localhost)

So you do not have to run `python3 -m http.server` every time, and so the dashboard does not fall over — three levels, from simplest to native.

## 1. Double-click (the simple way)
`OpenHealth.command` — double-click it in Finder. It brings the server up in the background (it survives closing the window) and opens the dashboard. If the server is already running, it just opens.

```
chmod +x OpenHealth.command   # once
```

## 2. Auto-start service (does not fall over, always available)
`com.openhealth.dashboard.plist` — a launchd agent: starts at login, restarts if it crashes (`KeepAlive`). The dashboard is always at `http://localhost:8770`.

Install (once — substitute the path and load it):
```
WEB_DIR="$(pwd)"
sed "s#__WEB_DIR__#${WEB_DIR}#" com.openhealth.dashboard.plist > ~/Library/LaunchAgents/com.openhealth.dashboard.plist
launchctl load ~/Library/LaunchAgents/com.openhealth.dashboard.plist
```
To unload: `launchctl unload ~/Library/LaunchAgents/com.openhealth.dashboard.plist`.

> This changes a system setting (auto-start at login). Install it deliberately, by hand.

## 3. Native app — OpenHealth.app (ready)
A full macOS `.app` with no Electron/Tauri and no dependencies — generated by the `make_macos_app.py` script (stdlib plus built-in macOS tools):

```
make app-install     # builds ui/web/dist/OpenHealth.app and puts it in ~/Applications
```

On launch the app does this: if nothing answers on 8770, it starts `server.py` in the background (picking up WHOOP credentials from `~/health-os/.env.whoop.local` if that file exists; log at `~/Library/Logs/OpenHealth.log`), waits for a response, and opens the dashboard in its own window in Chrome's app mode (its own Dock icon, no browser chrome); with no Chrome available, it opens in the default browser. The icon is rendered from `assets/icon.svg` (qlmanage → sips → iconutil, with a graceful fallback).

Limitation: the launcher hard-codes the absolute path of the current checkout — after moving the repository, re-run `make app-install`.

Future (a separate desktop batch): an embedded webview (Tauri) + local Claude/Codex passthrough for agent actions.

Real data (`data.local.json`) lives ONLY locally on the user's machine (in their health folder) and never lands in this repository. The dashboard reads it when present, and otherwise shows the demo.
